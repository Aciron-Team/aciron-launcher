# Как устроены репозитории

Исходник живёт в двух местах, и это не дублирование, а разделение ролей.

| | репозиторий | что там | ветка |
|---|---|---|---|
| **Исходник** | `Aciron-Team/aciron-launcher-src` (**private**) | код **с комментариями**, полная история | `source` |
| **Публикация** | `Aciron-Team/aciron-launcher` (public) | экспорт **без комментариев**, без служебных файлов | `main` |

Публичный репозиторий — производная. Его собирает `tools/make-github-export.mjs`:
вырезает комментарии и выкидывает то, чему в публичном доступе делать нечего
(`.cargo/config.toml` с ключами, `.env.local`, сборочные артефакты).

> **Почему не «приватная ветка»**: у GitHub нет приватных веток. Видимость
> задаётся репозиторием целиком — ветка в публичном репозитории публична.

## Повседневная работа

Работаем в этом репозитории, в ветке `source`:

```bash
git add -A
git commit -m "что сделано"
git push origin source
```

## Публикация в открытый доступ

```bash
node tools/make-github-export.mjs ../aciron-launcher-github
```

Дальше содержимое `../aciron-launcher-github` коммитится и пушится в публичный
репозиторий. **Пуш отсюда в публичный намеренно сломан** (`git remote -v` покажет
у `gh` заглушку вместо push-адреса): иначе однажды случайный `git push gh` увезёт
туда исходник с комментариями и служебными файлами.

## Забрать чужие правки из публичного

Публичный репозиторий читаемый, оттуда можно вытянуть правки:

```bash
git fetch gh
git log --oneline source..gh/main        # что нового
git cherry-pick -n <хеш>                 # перенести конкретный коммит
```

Конфликты будут почти в каждом файле, который правили: у публичной копии
комментарии вырезаны, поэтому git видит расхождение там, где его по смыслу нет.
Правило разрешения простое — **берём свой комментарий и их код**.

Заодно в публичной копии на месте вырезанных JSX-комментариев остаются пустые
выражения `{}`. Их не переносим — восстанавливаем комментарий по смыслу.

### Чем мы сознательно расходимся с публичным

Чтобы это не «чинили» заново при следующем переносе:

| что | у нас | в публичном | почему |
|---|---|---|---|
| первая вкладка гардероба | «Мои скины» | «Скины» | так просил владелец |
| вкладка образов | скрыта (строка в `TABS` закомментирована) | видима как «Образы» | скрыта намеренно, `ac6feb8` вернул её, посчитав недостижимой по ошибке. Код экрана рабочий |
| `setBust` из `1a36d0c` | не переносили отдельно | отдельный коммит | обоснование в нём неверное: `/skins`, `/capes` отдаются с `Cache-Control: no-cache`, а не с `max-age`, так что устаревшая картинка и не показывалась. Сам `setBust` приехал позже в составе `f623e3a`, где он уместен |

## Значения для сборки

Адреса сервисов и ключи не лежат в коде, а вшиваются при компиляции:

- `src-tauri/.cargo/config.toml` — заготовка рядом, `config.toml.example`
- `.env.local` — заготовка `.env.example`

Оба файла в `.gitignore` и не попадают ни в один из репозиториев. Без них проект
соберётся, но будет ходить на `example.invalid`.
